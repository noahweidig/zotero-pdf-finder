CiteVahti write-back

Advanced, off by default. If you use CiteVahti for claim-by-claim appraisal, ZotPDF is its safe write-back door: confirmed review tags land in Zotero only after a preview, and every write is audited and undoable.

Safety rules

  • Local only. The endpoint lives on Zotero's local server (127.0.0.1) and needs the token you generate.
  • Allowlisted tags. Only these prefixes can be written: cite:, fulltext:, retraction:, citation:, GRADE:, RoB2:, ROBINS-I:, Quality:. Anything else is refused, even with a valid token.
  • Previewable. A dry run shows the change before it happens.
  • Audited. Every applied write is recorded in a bounded local log (newest 500).
  • Undoable. Each write can be reversed.

Set up

  1. In Zotero's Advanced settings, enable Allow other applications on this computer to communicate with Zotero.
  2. Settings → ZotPDF → Allow CiteVahti to write tags.
  3. Generate a token, Copy it, and give it to CiteVahti.
  4. Test connection confirms the endpoint, the switch and the token.

Endpoints

The paths keep the /fullvahti/ prefix so existing CiteVahti installs keep working.

PathPurpose
/fullvahti/pingReports that write-back exists and which safety features it supports.
/fullvahti/tagAdd or remove allowlisted tags; supports dryRun.
/fullvahti/auditRead the audit log.
/fullvahti/undoReverse a recorded write.

Browse the log from Tools → ZotPDF → Write-back audit log, which also offers to clear it. Clearing deletes history only; it changes no tags.
